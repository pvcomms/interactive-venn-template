# Architecture

> The map. Read this instead of crawling the repo.

## In one paragraph

One static HTML file that draws a Venn diagram as SVG and lets you rewrite its content from a
panel underneath it. There is no build step, no server and no dependency. Two constants carry
everything: `LAYOUTS` is the solved circle geometry per layout, and the config object is the
labels, colours, copy and physics. `buildMarkup()` writes the entire SVG from those two,
`wireInteraction()` attaches behaviour to what it just wrote, and every edit in the panel mutates
the config and re-runs both. State lives in memory for the life of the tab. The only thing that
crosses a network boundary is the Google Fonts stylesheet in `<head>`.

## The tree

```
interactive-venn-template/
  index.html        the whole program: markup, style, script
  scripts/
    shot.mjs        writes docs/img/venn.png; imports Playwright by absolute path
  docs/
    img/venn.png    generated by shot.mjs; never edited by hand
    features/       one file per piece of work, numbered, never renumbered
```

## Data flow

```
LAYOUTS[layout] ─┐
                 ├──▶ buildMarkup() ──▶ svg.innerHTML ──▶ wireInteraction() ──▶ paint()
state.configs[layout] ─┘                                          │                  ▲
         ▲                                                        └──▶ wireReticle() │
         │                                                        └──▶ wireDrift()   │
         └──────────── customize panel edits ──────────────────────────────────────┘
                       (renderPanel binds inputs straight to the config object)
```

`rebuildAndKeepPanel()` is the arrow from an edit back to the top: it re-runs `buildMarkup()`
and `wireInteraction()` while leaving the panel DOM alone. Edits that only change text call
`paint()` instead, because the text is read at paint time and does not need new markup.

## What it reads and writes

| Path                         | Direction | What                                                     |
| ---------------------------- | --------- | -------------------------------------------------------- |
| `venn-config-<n>circle.json` | write     | `{layout, config}`, through a blob and an `<a download>` |
| a file chosen in _import_    | read      | the same shape, read with `FileReader` in the page       |
| Google Fonts                 | read      | the stylesheet and two font files, at load               |

Nothing is stored. There is no `localStorage`, no cookie, no session, no analytics and no
backend. Reloading the page discards every edit, which is what the export button is for.

## The model

A **layout** is geometry: `domains[]` with `cx`, `cy`, `r` and label placement, `pairs[]` with
the anchor point for each named intersection, one `triple`, and one `offrec` circle.

A **config** is content: `domains{}` keyed by domain id with label, color and desc; `pairs{}`
keyed by the sorted id pair; `triple`; `marker`; `offrec`; `physics`.

The two are matched by id. A layout and a config for different circle counts cannot be combined,
which is why the export payload carries `{layout, config}` together and import rejects a payload
whose `layout` is not a key of `LAYOUTS`.

## Invariants

Hit-testing reads `LAYOUTS`, never a copy. Everything per-circle is generated in a loop.
The page works from `file://`. No build step, no dependency.

## Known sharp edges

**The five-circle layout is honest about being incomplete.** Five circles cannot show all
thirty-one combinations of five sets. One set is drawn partly off-frame and the README says so
rather than implying the diagram is complete. A four-circle layout needs ellipses, not circles,
and is `docs/features/005-four-circle-layout.md` for that reason.

**The drift loop is double-driven.** rAF plus a `setInterval` that draws when rAF has been quiet
for three intervals, plus an `IntersectionObserver` that stops both when the SVG leaves the
viewport. All three parts are load-bearing; see `AGENTS.md`.

**`enterSet()` is a stub.** A second click on an already-filtered domain calls it, and it logs.
That is the extension point for anyone embedding the diagram, and it is deliberately not wired
to navigation here.

**The stroke-draw intro rewrites inline styles and then removes them.** After the circles draw
themselves, a timeout clears `strokeDasharray` and the inline `transition`. Code that sets
either on a `.set` circle during the first two seconds will be overwritten.

**`esc()` is the only escaping.** Every user string reaches the DOM through `innerHTML`, so any
new string that comes from the config must pass through it.
